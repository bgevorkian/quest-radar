# Памятка для продолжения разработки

Обновлено по локальным файлам 2026-10-05. Пользователь тестирует Зефрис в игре. Основные команды и правила интерфейса находятся в [README](README.md), обязательные правила работы — в [AGENTS.md](AGENTS.md).

## Текущая сборка

- Версия: 0.2.14; клиент тестирования Forever 1.60.1, build 70170, Interface 16001, ruRU.
- 4357 уникальных ID, 4439 записей с вариантами условий, 3980 ID с координатами на 49 картах. 377 ID без координат не отображаются.
- Источник: ATT `db/Camelot`, ревизия `788f116745f31e5b2da7171881919f3c44610140`. Актуальные значения смотреть в `research/import-summary.json` и `QuestRadar/Data.lua`.
- `research/zephras-import-audit.json`: сверено 145 обычных записей, расхождений с проверяемыми полями исходника нет. У 93459 нет координат. 94490 начинается с предмета и остаётся сомнительным. Скрытый триггер 93463 исключён.
- Это аудит переноса данных ATT, а не доказательство полноты серверных условий. Другие зоны включены, но аналогичная сверка исходных записей пока сделана только для Зефриса.
- Исходники и сгенерированные базы хранятся в отдельном Git-репозитории QuestRadar. `upstream/`, личные игровые отчёты, резервные копии и архивы сборок исключены из Git. Установка и публикация выполняются отдельно от коммитов.

## Доступность и данные персонажа

`Rules.Evaluate` возвращает `hidden`, `calculated` или `uncertain`. Жёлтый значок означает, что известные условия выполнены. Серый означает непроверенные условия. Уже взятые и выполненные обычные задания скрываются.

Проверяются класс, раса, фракция, уровень, профессия, репутация, предшественники и выполненные альтернативы. Ограничения родительских групп ATT сохраняются. Предшественники по умолчанию требуют всех подходящих записей; `sqreq` задаёт другое количество. Отрицательный ID означает задание в журнале. Несовместимые с персонажем ветки исключаются; неизвестные и breadcrumb-предшественники требуют осторожной оценки.

Если предшественник не указан, достаточно записанного уровня или другого известного условия открытия. Если таких данных нет, задание сомнительное. Повторяемость, предмет начала и другие непроверяемые условия тоже могут сделать его серым. Никогда не заменять неизвестное состояние API на «не выполнено» без основания.

Сборщик ATT убирает часть уровней 1 и наследуемых уровней. Для Зефриса импорт восстанавливает явные уровни из исходника. Технический fallback `lvl=1` не делает `minimumLevelKnown` истинным. Предметы начала в скомпилированной базе записаны также в `qss`.

Контекст берётся у текущего персонажа: журнал, `GetAllCompletedQuestIDs`, класс/раса, профессии, репутация. В тестах пользователя Skyborne Horde имел raceID 96, warrior — classID 1. Не подменять реальные ID догадками по обычному WoW.

Недавнее предложение NPC может подтвердить отметку на 60 секунд. Оно сбрасывается при изменении прогресса; координаты — позиция игрока рядом с NPC. Наблюдения не используются для автоматического вывода новых цепочек.

SavedVariablesPerCharacter: `QuestRadarDB`, `QuestRadarSettings`, `QuestRadarObservations`, `QuestRadarUnknownQuests`, `QuestRadarServiceObservations`, `QuestRadarBugReports`. Сохраняется до 200 наблюдений. Действующее минутное подтверждение между сессиями не переносится. Аддон ничего не отправляет наружу.

Сбор неизвестных принятых заданий добавлен 2026-10-05; запись файла ещё требует проверки в клиенте. `Map.lua` сохраняет первую запись каждого отсутствующего в `ns.ByID` задания в `QuestRadarUnknownQuests[questID]`; повторы не накапливаются. В API Forever `QUEST_ACCEPTED` передаёт один аргумент `questId`, не индекс журнала. Запись сохраняется даже без NPC, карты и координат; `offeredByNPC` берётся только из наблюдения того же задания не старше 60 секунд. Недостающее название запрашивается через `RequestLoadQuestByID` и дополняется при успешном `QUEST_DATA_LOAD_RESULT`. Старые записи остаются после обновления базы. Имя персонажа не собирается. Отчёт включает таблицу как `unknownQuests`; `/qradar clear` её не очищает. Файл и порядок ручной передачи описаны в README. Задания, принятые до установки, не восстанавливаются из журнала задним числом.

## Службы и сообщения об ошибках

`Services.lua` строит индексы по карте и NPC. `C_Minimap.GetTrackingFilter` связывает фильтр с текстурой из `GetTrackingInfo`; настройки отслеживания миникарты не меняются. Свои и нейтральные службы видны, учителя классов фильтруются по classID. Рядом стоящие NPC одного типа объединяются в пределах 0.6% карты. Если API не вернул иконку, отметка пропускается и причина попадает в технический отчёт. На карте нет технических подписей. Уровень кадров используется тот же проверенный `PIN_FRAME_LEVEL_QUEST_OFFER`.

Источники служб: MIT WaypointTracker/pfQuest, явные подписи учителей ATT, наблюдения сообщества Forever. Числовые преобразования из клиентской геометрии QuestieDB сохранены отдельно с URL источника. Координаты целей заданий не используются. Старые данные не считаются подтверждёнными в Forever. Импорт хранит ревизии и происхождение ролей; база не обещает полного покрытия всех NPC и учителей. Сводка: `research/service-import-summary.json`.

`Feedback.lua` слушает `PLAYER_INTERACTION_MANAGER_FRAME_SHOW` с enum из API Forever. Только `Creature` из `UnitGUID("npc")` служит основанием наблюдения; текущая цель не подставляется вместо отсутствующего NPC при автоматическом сборе. Ручное сообщение может использовать выбранную NPC-цель. Имя и GUID игрока не записываются. Снимок места создаётся при открытии формы; комментарий необязателен, тип проблемы обязателен. Общий текст выгрузки формируется в момент открытия отчёта и включает все коллекции. `/qradar clear` не удаляет ни коллекции, ни ручные сообщения.

Проверки: `tests/map.py` проверяет слои, текстуры, фильтры и подсказки; `tests/check.py` проверяет автоматические наблюдения, сообщение без комментария, неподвижный снимок места после перемещения, выгрузку и сохранение данных при повторной загрузке Lua. `tests/services_data.py` проверяет сгенерированную базу и согласованность импорта. Проверку файла SavedVariables, внешнего вида и полноты точек выполняют в клиенте.

## Детали совместимости, которые нельзя потерять

- Для видимости меток нужен `UseFrameLevelType("PIN_FRAME_LEVEL_QUEST_OFFER")`.
- Значок — atlas `QuestNormal`, а не нарисованный вопросительный знак или собственная иконка.
- Уровень в заголовке подсказки — сложность задания из `GetQuestDifficultyLevel`, не минимальный уровень получения. Цвет — `GetQuestDifficultyColor`. При отсутствии данных `[?]`.
- `QUEST_DATA_LOAD_RESULT` обновляет наведённую подсказку, не запускает повторный цикл запросов всей карты.
- Галочки используют `UICheckButtonTemplate`, текст явно `GameFontNormal`. Не возвращать мелкий шрифт по умолчанию.
- Меню у миникарты регистрируется через `IconAtlas` и `AddonCompartmentFunc` в TOC. Callback `QuestRadar_OpenSettings` глобальный.
- При разборе NPC GUID сначала сохранять результат `select(6, strsplit(...))` в переменную, потом `tonumber`: лишние возвращаемые значения иначе становятся вторым аргументом.

## Проверка и установка

Импорт и тесты запускаются из каталога проекта командами README. Обновление upstream отдельно от импорта; импорт отдельно от установки. Не обновлять upstream просто ради проверки документации или мелкого UI-исправления.

При выпуске поменять версию в TOC, записи диагностики `QuestRadar.lua`, записи сбора `Map.lua`, контексте `Feedback.lua` и заголовке README. Запустить подходящие проверки. Упаковать каталог `QuestRadar/` с сохранением этого верхнего уровня, включая `LICENSE-ATT.txt`, в `QuestRadar-<версия>.zip`.

Установка: каталог `QuestRadar/` копируется в `_classic_beta_/Interface/AddOns/`. Локальные пути и адрес Taildrive конкретного пользователя хранятся вне Git в `research/installation.local.md`. При работе через Taildrive сначала сверить действующую конфигурацию Tailscale.

Порядок установки:

1. GET заменяемых установленных файлов; сохранить в `research/installed-backups/<дата-время>/`.
2. PUT изменённых файлов, TOC последним. Не удалять соседние файлы и SavedVariables.
3. GET установленных файлов и побайтовое сравнение с локальными.
4. Пользователь делает `/reload`; при первой установке может потребоваться перезапуск клиента.

Для обычной правки документации установка в игру не нужна. При ошибке пользователя сопоставить отчёт последней карты и разговор с NPC: персонаж, ID задания, карта, статус и причина. Технические сведения добавлять в отчёт, не в подсказки карты.

## Ограничения и дальнейшая работа

- Условия ATT могут быть неполными или отражать логику коллекций, а не сервера. Ошибки сначала воспроизводить на конкретном задании.
- Для остальных зон стоит проверить потерянные при компиляции уровни, прежде чем распространять восстановление исходных данных за пределы Зефриса.
- Без координат источника нельзя честно поставить метку. Не использовать координаты целей или наград как координаты выдающего NPC.
- `altQuests` сейчас проверяет выполненные альтернативы; активные альтернативы отдельно не проверяются.
- Сбор предложений слушает `GOSSIP_SHOW` и `QUEST_DETAIL`; отдельной обработки старого `QUEST_GREETING` нет. Наблюдение неизвестного в базе задания само по себе не создаёт полноценную запись карты.
- По предыдущим игровым отчётам C_QuestLine возвращал пустые списки и на Зефрисе, и в Подгороде. Поэтому основной механизм — база и состояние персонажа. Это не доказывает, что API всегда пуст во всех местах; `/qradar scan` оставлен для проверки.
- 6609 ID из прежнего исследования клиента не равны 4357 заданиям текущего импорта и не содержат автоматически координаты и все условия.
- Игровую отрисовку, совместимость с другими аддонами и точность предложений проверяет пользователь. Успешные локальные тесты не дают оснований объявлять все 49 карт проверенными.

Это список ограничений для продолжения работы, а не обещание реализовать всё сразу. Следующий шаг определяется результатами тестирования пользователя.
